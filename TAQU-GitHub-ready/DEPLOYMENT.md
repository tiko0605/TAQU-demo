# 部署与公开访问

## 当前状态

当前目录没有发现部署平台配置、域名绑定、构建脚本、CI 工作流或已部署 URL。因此不能确认本 App 目前有在线部署，也不能确认它绑定任何公司账号或域名。

这是静态站点，发布时可直接托管 `outputs/` 中的三个运行文件：

- `index.html`
- `app.js`
- `styles.css`

无需构建命令，发布目录为 `outputs/`，没有额外 build 输出目录。

## 个人账号发布方式

### GitHub Pages

1. 确认代码和素材允许放到个人 GitHub 仓库；初期建议建立 **Private** 仓库。
2. 在项目根目录初始化 Git 并提交必要文件，具体命令见 `README.md`。
3. 先检查个人账号方案当前对 GitHub Pages 源仓库和站点访问控制的支持。GitHub Free 个人账号的 Pages 发布能力与仓库可见性有关；GitHub 文档当前说明，限制 Pages 网站为私有访问需要 GitHub Enterprise Cloud 组织。私有仓库不自动意味着 Pages 网站也是私有的。
4. 由于站点文件位于 `outputs/` 而非仓库根目录，选择 **GitHub Actions** 部署方式；工作流需要把 `outputs/` 上传为 Pages artifact 并发布。当前项目没有这份工作流，启用前需要由仓库所有者新增并检查它。
5. 首次部署后，在仓库 Pages 设置页读取 GitHub 实际分配的 URL。不要预先假定 URL、组织、账号或自定义域名。
6. 使用无痕窗口和手机尺寸验证站点、图片、图标、字体和主要交互。
7. 如果你的方案要求公开仓库或公开站点，而代码/素材尚未获准公开，不要为了发布而直接更改可见性；选择符合授权要求的个人静态托管服务，或先取得授权。

当前未在本目录创建 GitHub Actions 工作流，也未启用 Pages。启用前需由仓库所有者在个人账号中授权并操作。

### 其他静态托管

可将 `outputs/` 作为站点根目录上传到个人拥有的静态托管服务。需要在该服务的个人账号创建站点/项目、连接个人仓库或上传文件，并在控制台获取实际发布地址。当前项目没有任何平台专属构建步骤。

## 运行依赖和稳定性

本地静态文件可独立托管，但页面运行时会请求：

- `https://unpkg.com/lucide@latest`：图标脚本，使用浮动的 `latest` 版本。
- `https://fonts.googleapis.com` 与 `https://fonts.gstatic.com`：Noto Sans SC 字体。
- `https://images.unsplash.com`：页面样例图片。

项目中没有这些资源的本地副本，也没有 CDN 版本锁定或完整离线降级保障。网络不可达、URL 变化、服务策略或目标网络限制可能造成部分视觉素材不显示。迁移后的发布仍需验证资源许可和长期可访问性；如需可靠离线或可控版本，应另行评估本地化方案。
